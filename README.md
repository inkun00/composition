# 마음멜로디

초등학교 4~6학년이 화성학 전문용어를 배우지 않아도, 어울리는 화음 이야기와 가락을 듣고 고르며 자기 노래를 완성하는 작곡 웹앱입니다.

## 현재 단계: M6 개인 악보함

- 초등학생의 말로 구성한 화음 이야기 100개와 실제 기능화성 진행 적용
- 2/4·3/4·4/4·6/8박자 및 8~32마디 곡 길이 선택
- 마디별 화음에 맞는 가락 30개와 추천 가락 6개 제시 및 미리 듣기
- 일부 가락에는 화음 음 사이를 짧게 스쳤다가 돌아오는 음을 넣어 다양한 흐름 경험
- 추천 가락으로 전체 곡 채우기, 음표 길이 수정·삭제, 박자 합계 검사
- 피아노를 포함한 SoundFont 악기 128종에서 가락 악기를 선택하고, 검증된 반주 악기 34종으로 최대 4트랙 편성
- 조용조용·포근한 피아노·반짝 K-POP·통통 동요 등 어린이용 10가지 반주 느낌
- 동요·K-POP·애니메이션 OST·오페라·뮤지컬 장르 반주와 7가지 세부 연주 방식
- 무료 라이선스 SoundFont와 공공누리 음원 기반 악기·효과음 재생
- 카라오케 악보를 보며 녹음하거나, 녹음 없이 반주와 메인 가락을 함께 듣는 노래 연습 모드
- 마디별 가사, 곡 제목, 작곡가 입력
- 완성 악보를 A4 PDF로 저장(페이지당 8마디)
- 공유 링크로 곡을 전달하고, 받은 곡을 리메이크
- 리메이크 악보에는 최초 원작자를 수정할 수 없는 정보로 보존
- 작업 변경 후 1초 안에 브라우저에 자동 저장하고 새로고침 시 이어서 작업
- 같은 공유 링크의 리메이크 초안을 복원하면서 최초 원작자 정보를 그대로 보존
- Firebase Authentication 이메일·비밀번호 회원가입, Google 로그인과 사용자별 Firestore 악보함
- 클라우드 악보 저장·업데이트·사본 저장·불러오기·삭제
- 악보 사진과 악보 파일을 마디별로 검수한 뒤 편곡 프로젝트로 가져오기
- 가져올 시작·끝 마디를 선택할 수 있으며 32마디를 넘는 악보도 가져오기
- 메인화면의 기능 연습하기: 1~8마디 리듬·가락 연습, 칸 채우기와 악보 입력, 낮은 도~높은 도 8음
- 음표에 맞춘 가사 입력, 박자 부족·초과 안내, 화음 어울림 힌트, 다양한 리듬·가락 악기 및 연습 튜토리얼
- 연습한 음악 미리듣기·MP3 저장 및 막대·악보 모드 MP4 저장, 샘보드 공유 바로가기, 작곡 초안과 별도 자동 저장

## 실행

```bash
npm install
npm run dev
```

브라우저에서 [http://127.0.0.1:4173](http://127.0.0.1:4173)을 엽니다.

## 기능 연습하기

시작 화면 또는 작곡 화면의 메뉴에서 **기능 연습하기**를 엽니다. 마디 수와 박자를 정한 뒤
설정한 모든 마디를 함께 보며 음표 길이와 쉼표로 리듬을 만듭니다. 박자 입력 아래에서
음표마다 가사를 한 글자씩 넣거나 마디의 가사를 한 줄로 적을 수 있습니다. 음표 길이를 선택한 뒤
빈칸을 눌러 직접 배치하며, 다른 음표를 선택해도 이미 배치한 리듬은 바뀌지 않습니다.
색칠한 칸을 다시 누르면 해당 음표나 쉼표가 삭제됩니다. 너무 긴 가사는 다음 마디로 나눠 주세요.

각 마디의 **리듬 미리듣기**는 박자가 부족하거나 넘쳐도 입력된 음표만 연주합니다.
다른 마디가 미완성인 상태에서도 사용할 수 있고 가락 단계에서도 리듬 악기로 들을 수 있습니다.
준비 중에는 취소하고 재생 중에는 멈출 수 있으며, 미리듣기로 음표나 가사가 바뀌지는 않습니다.

음표 입력 위에서 먼저 리듬 악기를 선택할 수 있습니다. **악보 추가하기**로 최대 세 악보에
서로 다른 악기와 리듬을 넣고 **리듬 함께 듣기**로 동시에 들어 보세요. 미완성 리듬도 함께 들을 수 있고,
각 악보의 같은 마디는 같은 시점에 시작합니다. 마디 수와 박자·빠르기는 모든 악보가 공유합니다.
모든 악보의 마디를 완성하면 리듬만으로도 미리듣거나 MP3·MP4로 저장할 수 있습니다.
가락 만들기는 선택입니다. 원하면 첫 악보에 가락을 붙이고 추가 악보는 리듬 반주로 함께 연주합니다.
MP3·MP4에도 모든 악보의 소리가 들어가며 MP4는 각 악보에 입력한 음표와 가사를 보여 줍니다. 악보별 리듬과 악기는 자동 저장됩니다.

모든 마디의 박자가 맞아야 **가락 만들기**로 넘어갈 수 있으며 완성한 리듬의 음표·쉼표·길이·가사를 그대로 사용합니다. 가락 단계에서도
음높이뿐 아니라 음표 길이·쉼표·가사를 수정할 수 있으며 박자 검사 안내를 확인할 수 있습니다.
마디 바로 위에서 칸 채우기와 악보 입력을 고를 수 있으며 두 방식은 같은 음표를 공유합니다. 악보 음표에도 계이름을 표시합니다.
첫 화음은 장·단화음과 7화음 등 14개 중에서 고릅니다. 다음 마디부터는 앞 화음과 자주 연결하는 후보를 표시합니다.
앞 화음을 바꾸면 뒤쪽에서 연결이 맞지 않는 화음도 후보 안에서 바꾸고 안내하며, 리듬·가락·가사는 보존합니다.
화음 힌트는 화음 구성음, 박의 위치, 이웃 음과 다음 마디로 이어지는 움직임을 함께 살펴봅니다.
짧게 지나가거나 되돌아오는 음은 가락에 색채를 더할 수 있으므로 화음 구성음이 아니라는 이유만으로 오류라고 하지 않습니다.
곡의 끝과 마디의 끝도 구별하며, 힌트가 없더라도 음악의 좋고 나쁨을 판정하거나 편안한 소리를 보장하지 않습니다.
안내를 누르면 바꿔 볼 음을 선택할 뿐 가락을 자동으로 수정하지 않습니다. 직접 들어 비교해 보세요.
**처음이라면? 연습 안내**에서 네 단계의 예시를 볼 수 있습니다.

상단 단계는 **1 리듬 만들기 → 2 가락 만들기(선택) → 3 음악 저장하기 → 4 음악 공유하기**입니다.
**음악 저장하기**는 입력 화면에서 별도로 열리며 돌아와도 음표·가사·악기와 편집 단계가 유지됩니다.
입력 영역 하단에서도 완성한 리듬이나 가락을 미리듣거나 MP3·MP4로 저장할 수 있으며 **음악 저장 설정**으로 저장 화면을 엽니다.
가락 단계에서만 가락 악기를 선택하며 리듬 단계에서는 위에서 고른 리듬 악기를 사용합니다.
MP4 저장 화면의 **막대 모드**는 음표 길이를 막대의 길이로, 가락의 높낮이를 막대의 위치로 보여 주며 계이름은 막대 안에, 가사는 아래에 표시합니다.
**악보 모드**는 마디를 연결한 악보와 가사만 보여 줍니다. 두 모드 모두 검정 배경과 흰색 표시를 사용하고, 연주 중인 부분에 잔광·맥동·재생선 모션을 24fps로 담습니다. 모든 악보의 소리도 함께 저장합니다.
저장 화면에서 실제 영상 화면을 미리 살펴보고 위치 조절로 다른 마디도 확인할 수 있습니다.
가사가 있다면 해당 악보의 음표 아래에 함께 표시합니다.
가사 없이도 MP4를 저장할 수 있습니다. 가사를 입력했다면 모든 가사 글자에 음표가 있어야 저장할 수 있으며
최신 Chrome·Edge의 영상 인코딩을 사용합니다.
연습은 작곡 프로젝트와 별도로 이 브라우저에 자동 저장됩니다.
**음악 공유하기**는 지정된 [샘보드](https://samboard.vivasam.com/studentEntry/?brdId=brd-0RXAMP8AGEZ2B)를 새 창으로 엽니다.
저장한 파일은 사용자가 샘보드에서 직접 올리며 앱이 자동으로 업로드하거나 게시하지 않습니다.

실제 브라우저 검증은 `npm run dev -- --port 4175` 실행 후 `node scripts/verify-practice.mjs`로 수행합니다.
다른 주소는 `PRACTICE_URL`, Chrome 실행 파일 위치는 `CHROME_PATH` 환경변수로 지정할 수 있습니다.
입력 흐름·MP3의 실제 음높이·MP4의 리듬 및 가락 표시·모바일 스크롤을 확인하고
`artifacts/practice/`에 테스트 파일과 화면을 저장합니다.

`node scripts/verify-practice-layers.mjs`는 세 악보의 동시 재생·악보별 입력·복원·MP3와 모바일 화면을 확인하고 `artifacts/practice-layers/`에 결과를 저장합니다.

## 제출용 ZIP 만들기

```bash
npm run build:portable
```

`artifacts/maeum-melody-portable/` 폴더와 `artifacts/maeum-melody-portable.zip`이 만들어집니다.
ZIP을 원하는 위치에 모두 압축 해제한 뒤 `index.html`을 Edge·Chrome에서 열면 실행됩니다.
이미지·효과음·비트 샘플과 앱 코드는 패키지에 포함하며, 악기 음원·글꼴과 기존 Firebase는 인터넷으로 연결합니다.
수신 컴퓨터에는 npm이나 개발 서버가 필요 없습니다.

Google 로그인은 `file://` 주소에서 지원되지 않으므로 Windows에서는 함께 제공하는
`전체기능-실행.cmd`를 사용합니다. Windows 기본 PowerShell로 로컬 서버를 켜고
Firebase 허용 도메인인 `http://localhost:4173`을 엽니다. 포트가 사용 중이면 빈 포트를 선택합니다.
실행 창에서 Enter를 누르면 서버가 종료됩니다. Node.js 설치는 필요 없습니다.

악보 사진 인식은 이 로컬 서버 화면에서 `start-score-reader.cmd`를 추가로 실행합니다.
사진 인식 도우미에는 기존과 동일하게 Node.js 및 Python/인식 모델 준비가 필요합니다.
MusicXML·MXL 가져오기는 도우미 없이 사용합니다. 자세한 안내는 패키지의 `실행안내.html`에 있습니다.

로컬 공유 링크와 PDF QR은 현재 온라인 앱 `https://maeum-melody.vercel.app`을 사용합니다.
다른 컴퓨터로 옮길 작업은 기존 클라우드 악보함에 저장해 주세요.

## Firebase 연결

1. Firebase Console에서 프로젝트와 Web App을 만듭니다.
2. Authentication의 로그인 제공업체에서 이메일/비밀번호와 Google을 활성화합니다.
3. Cloud Firestore 데이터베이스를 만든 뒤 `firestore.rules`를 배포합니다.
4. `.env.example`을 참고해 로컬 `.env.local`과 Vercel 환경변수를 등록합니다.

```bash
npx firebase-tools login
npx firebase-tools use --add
npx firebase-tools deploy --only firestore:rules
```

Firebase 환경변수가 없는 경우 기존 로컬 자동 저장은 그대로 작동하며, 내 악보함에는 연결 안내가 표시됩니다.

## 악보 사진 읽기

`화음 이야기를 골라요`의 `악보 가져오기`에서 PNG·JPG·WEBP 사진을 선택하면 로컬의
[homr](https://github.com/liebharc/homr)로 읽고, 마디별로 확인한 뒤 프로젝트로 가져옵니다.
첫 실행에는 Python 3.11과 인식 모델을 준비하느라 시간이 걸릴 수 있습니다.
사진은 유료 API나 외부 인식 서버로 전송하지 않습니다. MusicXML·MXL 파일은 설치 없이 바로 읽습니다.
PDF는 필요한 페이지를 이미지로 저장한 다음 선택해 주세요.
인식이 끝나면 시작 마디와 끝 마디를 고릅니다. 악보가 길어도 12마디씩 넘겨 보며 확인할 수 있습니다.
가져오기 마디 수와 이미지 파일 크기에 앱 자체 상한은 없지만, 긴 악보는 기기의 메모리·처리 속도와 저장 공간에 따라 시간이 걸리거나 실패할 수 있습니다.

로컬 개발 서버(`npm run dev`)에서는 인식 도우미가 서버에 포함됩니다. 배포된 앱에서 사진을
읽으려면 `악보 가져오기` 팝업에서 로컬 도우미를 받아 실행해야 합니다. 로컬 도우미에는 Node.js가 필요합니다.
팝업은 Windows에서 도우미 다운로드·실행, 연결 확인, 인식 환경 준비 순서를 보여 줍니다.
Node.js나 Python이 없으면 공식 설치 페이지 링크를 안내하며, 도우미 연결은 자동으로 다시 확인합니다.
휴대폰과 macOS·Linux에서는 배포판의 간편 도우미 실행을 지원하지 않으므로 MusicXML·MXL 파일을 이용하거나 Windows 컴퓨터에서 사진을 읽어 주세요.

## 검증

```bash
npm test
npm run build
node scripts/verify-m4.mjs
```

`verify-m4.mjs`는 로컬 서버가 실행 중일 때 Edge의 Chromium 엔진으로 A4 PDF 다운로드와 8·16마디 페이지 분할을 확인합니다.

제품 요구사항은 [PRD.md](./PRD.md), 음원 출처와 라이선스는 [THIRD_PARTY_NOTICES.md](./THIRD_PARTY_NOTICES.md)를 참고합니다.
