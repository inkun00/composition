# 음악 학습 게임 조사와 재설계

조사일: 2026-11-06. 초등학생이 처음 배우는 음표 길이·박자표·빠르기·셈여림·악보 기호를 대상으로 한다. 현재 화면은 설명, 조작 패널, 객관식 문제를 잘 제공하지만 플레이어의 행동이 게임 속 사건으로 이어지지 않아 학습 도구에 가깝다. 이번 수정에서는 색상이나 배지만 바꾸는 대신 **목표 → 직접 행동 → 즉시 결과 → 다음 도전**을 화면의 중심으로 옮긴다.

## 현재 구현에서 바꿔야 할 지점

| 현재 경험 | 게임으로 느끼기 어려운 이유 | 수정 방향 |
| --- | --- | --- |
| 같은 크기의 단원 카드와 긴 설명 | 시작부터 배우는 목록을 읽어야 하고 하고 싶은 사건이 없다. | 다섯 구역이 있는 탐험 지도, 내 캐릭터, 현재 임무를 첫 화면의 중심에 둔다. 각 구역에서 무엇을 완성하는지 한 문장으로 보여 준다. |
| 자유롭게 음표를 넣는 빈 마디 | 정해진 예산·목표·문제 조건이 없어 어떤 선택도 비슷하게 끝난다. | 박자 수와 사용할 음표 조건이 있는 짧은 퍼즐을 준다. 맞게 만든 음표 길이가 다리의 길이가 되고 캐릭터가 건너간다. |
| 듣기 버튼과 네 번 두드리기 | 연습의 성공이 세상에 변화를 만들지 않고 끝이 약하다. | 먼저 듣기, 카운트인, 내 차례, 박마다 판정, 완주 결과가 이어지는 한 라운드를 만든다. 맞춘 박으로 캐릭터가 전진하거나 빛을 켠다. |
| 셈여림 목록·설명 카드 | 기호 선택이 음악적 목표를 해결하는 데 필요하지 않다. | 뒤집힌 카드에서 실제 기호와 뜻을 기억하고 찾아 연결한다. 셈여림 짝을 찾으면 해당 세기로 소리를 듣는다. |
| 마지막 객관식 퀴즈만 성취 기록 | 조작보다 글을 읽고 답하는 비중이 높다. | 퀴즈는 복습으로 남기고, 조작 미션을 끝내는 것도 구역 완성으로 인정한다. 결과 화면에 이번 행동으로 배운 내용을 짧게 연결한다. |

## 권장하는 세 가지 핵심 게임 흐름

### 1. 박자 다리 만들기

- 목표: 정해진 박자만큼 음표 블록으로 다리를 만들어 친구를 건너게 한다.
- 행동: 예를 들어 2/4박자의 두 박을 2분음표 하나, 4분음표 둘, 8분음표 넷 중 미션 조건에 맞게 만든다. 버튼으로 추가·되돌리기가 가능해야 한다.
- 결과: 블록의 가로 길이는 음표 길이에 비례한다. 반 박은 한 박 블록의 절반이고, 목표에 맞을 때만 캐릭터가 완주한다. 넘거나 부족하면 어디가 다른지 표시한다.
- 진행: 자유 채우기 → 특정 음표 사용 → 쉼표 포함 → 3/4·4/4처럼 조건을 점진적으로 추가한다. 스테이지가 바뀌면 실제 조건도 달라져야 한다.
- 학습 보호: 4분음표를 한 박으로 세는 기준을 명시한다. 음표의 개수만 맞추는 게임으로 만들지 않는다.

### 2. 리듬 따라가기

- 목표: 제시된 리듬의 음이 시작하는 순간에 눌러 열차와 함께 목적지까지 간다.
- 행동: 먼저 듣기 → 네 박 준비 신호 → 내 차례 → 한 개의 큰 입력판으로 연주한다. 클릭·터치와 키보드 입력을 동등하게 지원한다.
- 결과: 현재 박과 타이밍 지점을 보여 주고 누른 직후에 알맞음·조금 빠름·조금 늦음을 알려 준다. 긴 음표는 시작에 한 번 누르고 다음 음까지 기다린다. 홀드 시간을 채점하는 방식은 아니며, 쉼표를 포함해 불필요하게 더 누른 입력은 별도로 계산한다.
- 진행: 80 BPM에서 4분음표 → 쉼표 → 2분음표·8분음표의 세 구간으로 넓힌다. 느긋한 판정과 정확한 판정을 선택하며, 빠르기 자체를 바꿔 보는 체험은 기존 음악 도감에서 제공한다.
- 학습 보호: 초등 입문에서는 넉넉한 판정과 반복 듣기를 제공한다. 시각 표시를 끄는 도전은 선택 사항이며 기본 접근을 잠그지 않는다. 백그라운드 탭에서는 라운드를 중단한다.

### 3. 악보 기호 짝 맞추기

- 목표: 뒤집힌 카드에서 악보 기호와 해당 뜻의 짝을 모두 찾는다.
- 행동: 카드를 두 장씩 열어 기호와 설명을 기억한다. 예를 들어 mf 기호와 ‘조금 세게’, 도돌이표와 ‘되풀이하여 연주하기’를 연결한다. 글만 읽는 대신 실제 기호의 모양을 알아보게 한다.
- 결과: 알맞은 짝은 열린 상태로 남고, 틀린 짝은 확인한 뒤 다시 뒤집힌다. 남은 짝, 시도 횟수, 완료 결과를 보여 준다. 실제 셈여림 소리도 확인할 수 있게 한다.
- 진행: p·mf·f와 음자리표·도돌이표 등 단순한 카드부터 시작해 기호와 뜻을 섞는다. 빠른 시간만을 목표로 삼지 않고 적은 시도로 기억해 연결하는 재미를 준다.
- 학습 보호: mf는 상대적 세기이다. 손가락 압력이나 특정 볼륨 백분율을 정답으로 강요하지 않는다. 높이·빠르기·세기를 섞어 잘못 설명하지 않는다.

실제 구현 게임 식별자는 박자 다리 `bridge`, 리듬 기차 `train`, 악보 기호 짝 맞추기 `memory`로 구성한다. 게임마다 최고 별 수와 최고 점수를 별도로 저장하여 재도전에서 기록이 낮아지지 않게 한다.

## 진행·보상과 플랫폼 결정

- 한 판의 시작과 끝을 분명히 한다. 짧은 미션 목표, 현재 단계, 행동에 따른 즉시 반응, 성공 후 결과 화면이 필요하다.
- 별·악기·친구 같은 수집 요소는 완료한 미션과 연결한다. 같은 미션을 반복해 보상을 무한히 쌓는 대신 최고 기록이나 첫 완료를 저장한다.
- 오답을 감추거나 단순히 실패 표시만 하지 않는다. 왜 달랐는지 보여 주고 바로 재도전할 수 있어야 한다. 강제 광고, 접속 보상, 결제, 온라인 순위는 이번 목표에 필요하지 않다.
- 권장 기반은 기존 React/Vite, SVG 게임 무대, Web Audio의 오디오 시계다. 단순 캐릭터 이동·블록 조립·한 버튼 입력은 새 엔진 없이 구현할 수 있다. 다수의 물리 충돌·대규모 월드가 생기면 Phaser 도입을 재검토한다.
- 키보드로도 게임의 전체 목표를 달성할 수 있어야 한다. 색상에만 기대지 않고 기호·문장·위치를 함께 사용한다. 동작 줄이기 환경에서는 이동 연출을 줄여도 게임 상태와 판정은 동일하게 제공한다.

## 코드·에셋 사용 범위

참고 게임들의 코드·화면·캐릭터·음원은 이번 저장소에 복사하지 않는다. 제작사의 공개 소개는 분석 자료이며 자산 사용 허락을 뜻하지 않는다. Chrome Music Lab의 공개 코드 라이선스와 상업 게임의 자산 권한도 구별한다. 이번 구현은 자체 미션 데이터, 자체 SVG 무대, 앱에 이미 있는 에셋, 직접 합성한 소리를 사용한다.
