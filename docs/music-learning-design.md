# 음악 학습하기 설계

작성: 2026-11-06. 대상은 음표를 처음 배우는 초등학생이다. 현재 첫 화면은 세 가지 게임을 고르는 `리듬별 구조대` 탐험 지도다. 처음 구현한 체험·설명·퀴즈는 음악 도감으로 유지한다. 게임 사례와 변경 이유는 [음악 학습 게임 조사와 재설계](music-learning-game-research.md)에 정리한다.

## 플랫폼 선택

| 후보 | 용도와 라이선스 | 이번 기능에서의 판단 |
| --- | --- | --- |
| [React](https://github.com/facebook/react) + 기존 Vite | 화면·상태·접근 가능한 버튼, MIT | 기존 앱 안에서 구현. 별도 서비스나 계정이 필요 없다. |
| [VexFlow](https://github.com/vexflow/vexflow) | 실제 악보를 그리는 TypeScript 라이브러리, MIT | 이미 설치된 패키지를 지연 로딩해 음표·쉼표·박자표를 표시한다. |
| [Web Audio API](https://www.w3.org/TR/webaudio/) | 브라우저 오디오 시계·합성음·음량 조절 | 짧은 음표와 메트로놈을 앱에서 합성한다. 별도 음원 에셋이나 추가 패키지가 필요 없다. |
| [Tone.js](https://github.com/Tonejs/Tone.js) | 음악용 Transport·합성음·시퀀싱, MIT | 복잡한 다중 트랙에는 유용하나 이번 단일 학습 패턴에는 도입하지 않는다. |
| [Phaser](https://github.com/phaserjs/phaser) | Canvas/WebGL 2D 게임 엔진, MIT | 캐릭터 충돌·월드 탐험보다 버튼·악보·박자 조작이 중심이므로 도입하지 않는다. |
| [Chrome Music Lab](https://github.com/googlecreativelab/chrome-music-lab) | 직접 조작하는 음악 실험의 공개 코드, Apache-2.0 | 체험 학습 방식을 참고한다. 코드·이미지·음원을 복사하지 않는다. 저장소는 2026-04-19 보관 상태다. |

최종 구성은 **React/Vite + 지연 로딩하는 VexFlow + Web Audio API**다. 별도의 서버, 로그인, 유료 서비스, 게임 엔진 없이 기존 앱에서 실행한다. 일러스트와 아이콘은 앱의 기존 에셋을 재사용하고 새 원격 에셋은 불러오지 않는다. 학습 문장, 문제와 정답 설명, 시뮬레이션 규칙은 앱의 독립된 학습 모듈이 소유한다.

## 학습 흐름

주 활동은 **지도에서 임무 선택 → 조작 → 게임 세계의 변화 → 구간 결과 → 다음 도전**으로 이어진다. 다리 5개, 열차 3개 역, 기억 카드 3개 별자리를 제공한다. 게임의 최고 점수와 별은 도감의 완료 도장과 별도로 기기에 저장한다. 열차는 준비 박 네 번 후 음 시작 타이밍을 판정하고, 다른 두 게임은 시간 제한 없이 조작한다. 강제 접속이나 계정·분석 서버는 없다.

음악 도감의 각 단원은 **알아보기 → 눌러 보고 들어보기 → 세 문제 이상 도전 → 다시 연습하기**로 이어진다. 틀리면 정답 이유와 관련 체험을 안내하며 재시도를 허용한다. 저장을 차단한 브라우저에서도 현재 학습과 게임은 계속할 수 있어야 한다.

| 단원 | 체험 | 확인 문제 예시 (각 3개 이상) |
| --- | --- | --- |
| 음표와 쉼표 (`notes`) | 온음표·2분·4분·8분음표를 고르면 소리가 유지되는 시간과 차지하는 박자 칸을 함께 표시. 4분쉼표를 통해 침묵도 한 박을 차지함을 확인 | 4분음표 기준에서 2분음표는 몇 박? / 8분음표 두 개는 몇 박? / 4분쉼표에서는 어떻게 하나? / 온음표는 몇 박? |
| 박자와 한 마디 (`meter`) | 2/4·3/4·4/4를 선택하고 음표·쉼표 버튼으로 한 마디 채우기 | 2/4는 무엇을 뜻하나? / 2/4를 딱 채우는 음표는? / 3/4의 박을 세는 방법은? / 세로줄은 무엇을 나누나? |
| 빠르기 (`tempo`) | 같은 네 박자를 BPM 슬라이더로 느리게·빠르게 재생하고 한 박자 시간 비교. 박에 맞춰 두드려 보기 | 4분음표 = 60은 1분에 몇 박? / 더 빠르게 연주하는 BPM 고르기 / 빠르기가 달라도 음표의 박 수가 같은지 확인 |
| 셈여림 (`dynamics`) | pp–p–mp–mf–f–ff 및 점점 세게·여리게를 같은 패턴으로 비교 | mf의 뜻은? / p와 f 중 더 여리게 연주하는 것은? / 크레셴도의 뜻은? / 데크레셴도의 뜻은? |
| 악보 기호 (`symbols`) | 높은·낮은음자리표, 세로줄, 끝세로줄, 도돌이표, 올림·내림·제자리표를 이름·설명·실제 기호로 탐색 | 높은음자리표가 정하는 줄은? / 도돌이표를 만나면 어떻게 하나? / 끝세로줄은 무엇을 알려 주나? |

실제 문제 데이터는 각 단원의 학습 목표를 유지하며 조정할 수 있다. 기호만 제시하지 않고 한글 이름과 의미를 함께 보여 준다. 음표·쉼표는 실제 악보 모양으로 표시하며 기기별 유니코드 글꼴 차이에 의존하지 않는다.

## 음악 내용의 기준

- 이 놀이터는 **4분음표를 한 박으로 세는 기준**을 명시한다. 이 기준에서 온음표 4박, 2분음표 2박, 4분음표 1박, 8분음표 반 박이다. 같은 종류의 쉼표도 같은 시간을 차지한다. 2분음표를 언제나 두 박이라고 일반화하지 않는다.
- 2/4는 4분음표를 한 박으로 하여 한 마디에 두 박이다. 음표를 반드시 두 개만 넣는다는 뜻이 아니다. 3/4·4/4도 같은 원리로 설명한다. 이번 입문 단원에서는 겹박자를 섞지 않는다.
- BPM은 1분 동안의 기준 박 수다. 실제 길이는 `박 수 × 60 / BPM`초다. 60 BPM의 2분음표는 2초, 120 BPM에서는 1초지만 둘 다 이 기준에서 두 박이다.
- `mf`는 메조 포르테, 조금 세게라는 상대적인 셈여림이다. `p`는 여리게, `f`는 세게다. 고정된 데시벨·정확한 퍼센트를 음악 이론의 정답으로 가르치지 않는다.
- 크레셴도는 점점 세게, 데크레셴도는 점점 여리게다. 빠르기 변화와 혼동하지 않도록 같은 음정·리듬을 유지하며 음량만 바꾼다.
- 첫 재생은 사용자의 클릭에서 시작한다. 화면을 떠나거나 재생을 중지하면 예약된 소리와 진행 표시를 함께 정리한다. 소리 재생이 지원되지 않더라도 박자·기호 설명과 퀴즈를 이용할 수 있다.

내용 확인 자료: [음표 길이](https://www.musictheory.net/lessons/11), [마디와 박자표](https://www.musictheory.net/lessons/12), [RIAM 공식 연주 용어표](https://riamexams.com/upload/202111/30/202111300951540512.pdf). 문장이나 문제를 복제하지 않고 원리를 바탕으로 한국어 학습 콘텐츠를 작성한다.

## 화면과 접근성

- 큰 학습 버튼과 선택 상태를 사용하고 색상 외에도 이름·숫자·문장으로 피드백한다.
- 드래그를 요구하지 않는다. 음표 추가·되돌리기·비우기·재생을 일반 버튼으로 제공해 터치와 키보드로 동일하게 조작할 수 있게 한다.
- 현재 단원, 재생 상태, 퀴즈 결과를 읽을 수 있는 텍스트로 제공한다. 기호에는 이름을 부여한다.
- 잘못 채운 마디는 몇 박이 부족하거나 넘었는지 알려 준다. 단순 실패 표시로 끝내지 않는다.
- 작은 화면에서는 세로로 배치한다. 동작 줄이기 설정에서 장식 애니메이션을 줄이고 내용과 상태 표시는 유지한다.
- 첫 화면·다른 활동으로 돌아갈 수 있고 학습에서 나올 때 작곡 초안에 영향을 주지 않는다.

## 검증 계획

1. 단위 검사: 음표·쉼표 길이, BPM 시간 환산, 한 마디 합계와 초과 판정, 정답·진행 저장 규칙.
2. 오디오 검사: 사용자 제스처 시작, 중지·화면 이동·탭 숨김 시 취소, 쉬는 구간에서 발음하지 않음, 셈여림 비교의 상대적 음량.
3. 화면 검사: 시작 화면 진입, 다섯 단원 이동, 음표·박자표 렌더링, 한 마디 채우기와 초기화, 오답 재시도, 학습 완료 표시와 새로고침 후 복원.
4. 접근성·반응형 검사: 키보드만으로 조작, 명확한 레이블·포커스, 390px 모바일 및 데스크톱에서 잘림·가로 넘침 없음.
5. 저장소 필수 검사: `npm run check:file-lines`, 관련 테스트 및 `npm run build`. 기존 레거시 파일은 동결 상한을 늘리지 않고 역할별 학습 파일로 분리한다.

VexFlow 라이선스 원문은 [배포 라이선스 파일](../public/third-party-learning-licenses.txt)에 보존한다. Phaser, Tone.js, Chrome Music Lab은 조사 자료이며 이번 배포물에 코드나 에셋을 포함하지 않는다.

## 초기 구현 검증 결과 (첫 커밋)

- 시작 화면과 작곡 화면 메뉴에 `음악 학습하기` 진입점을 추가했다. 기존 작곡 상태는 활동을 다녀와도 유지한다.
- 다섯 단원, 체험 활동, 18개 퀴즈와 완료 도장 저장을 구현했다. 학습 화면·오디오·데이터·악보·진도 저장을 별도 파일로 나누었다.
- 파일 크기 검사와 프로덕션 빌드 통과. 전체 테스트 215개 파일, 2,386개 항목 통과(`npm test -- --maxWorkers=2`).
- `node scripts/verify-music-learning.mjs`로 실제 브라우저에서 재생 길이·쉼표 무음·셈여림·퀴즈 재도전·저장 복원·메뉴 복귀를 확인했다. 1440px 데스크톱, 375px 휴대폰, 667×375 가로 화면의 총 13개 배치에서 페이지 가로 넘침이 없었다.
- 검증 보고서와 화면 캡처는 `artifacts/music-learning/`에 저장한다. 긴 악보는 휴대폰에서 내부 스크롤과 키보드 방향키로 읽는다.

## 게임 개편

| 게임 | 플레이어 행동 | 세계의 변화·보상 |
| --- | --- | --- |
| 음표 다리 구조대 | 제한된 조각으로 목표 박 수와 음표 조건을 맞춘다. 하나 빼기·다시 놓기로 고친 뒤 건너기를 선택한다. | 다리가 완성될 때 새 친구가 반대편으로 이동한다. 다섯 친구 구조·구간 별·점수를 기록한다. |
| 별빛 리듬 열차 | 목표 리듬을 먼저 듣고 네 박 준비 후 음 시작마다 터치·스페이스 입력을 한다. 쉼표에서는 기다린다. | 성공할 때 도착등과 열차 위치가 바뀐다. 즉시 판정·콤보·구간 결과·최종 메달을 제공한다. |
| 기호 별자리 맞추기 | 뒤집힌 기호·뜻 카드의 위치를 기억해 짝을 찾는다. 오답은 확인 후 직접 다시 뒤집는다. | 맞춘 짝마다 별이 켜지고 별자리를 완성한다. 셈여림 짝은 해당 세기의 실제 소리로 확인한다. |

각 게임의 최고 별과 최고 점수는 독립적으로 보존해 재도전 결과가 낮아져도 기존 기록은 유지한다. 자체 SVG 무대와 합성음으로 구현했으며 참고 게임의 캐릭터·음원·코드를 복제하지 않았다. 검증 스크립트는 `scripts/verify-music-games.mjs`, 보고서·화면은 `artifacts/music-games/`다.

개편 후 전체 테스트 223개 파일·2,413개 항목, 파일 크기 검사와 프로덕션 빌드가 통과했다. 실제 브라우저에서 다리 5단계·별자리 3단계·열차 3구간을 완주하고 11개 리듬 입력, 쉼표 입력 방지, 최고 기록 복원, 셈여림 소리, 12개 반응형 화면을 확인했다. 기존 도감의 18개 퀴즈와 13개 화면 검사도 통과했다.
